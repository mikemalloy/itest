# itest-cli 0.2.0

Integration inventory, verification, and auth testing for Terraform-managed AWS
infrastructure.

ITest reads your Terraform and extracts the integration points it describes —
the security-group rule that says *A can reach B on 5432*, the IAM grant that
says *this role may call that queue*, the event source mapping that says *this
queue drives that function* — as a content-hashed, diffable inventory you
review like code. One command then verifies every point against the live
account, read-only, reporting coverage per integration point, not per test.

## What's in 0.2.0

- **Five detectors:** `sg_edge` (security-group reachability), `iam_edge`
  (role to resource, with wildcard, cross-stack and managed-policy flags),
  `event_edge` (event source mappings, DLQ redrive, Lambda permissions),
  `route_edge` (API Gateway REST and HTTP APIs), and `lb_edge` (the load
  balancer and container spine, including blue/green alternate target groups).
- **The `itest-implementer` skill** — six recipes, one per point type plus the
  HTTP probe, over a shared `conftest.py` that resolves every ARN and ID from
  `terraform show -json` at test time, so nothing is hardcoded.
- **Environment policy and tier gating.** A committed
  `.itest/environments.yaml` says which tiers each environment may run; a local
  binding says where this checkout points. Both must allow a tier or it is gated
  out of collection, and an environment named or flagged production refuses
  mutating tests outright.
- **The HTTP probe and its OpenAPI sweep** — an active-tier, per-endpoint
  401/403 check driven by your spec, one probe registered per operation. The
  probe is bodyless by construction, follows no redirects, and retries nothing.
- **`verify --redact`**, which pseudonymizes account IDs and high-entropy
  tokens in every output format before you share a run, while keeping
  human-readable resource names intact on purpose.
- **Terminal output** styled over the canonical strings — colour is a layer on
  the text, never a re-layout, and it switches itself off when stdout is not a
  terminal. `--output json` and `--output junit` are never styled.

## What it has been run against

Real Terraform states, listed row by row in
[docs/compatibility.md](../compatibility.md): the author's own systems plus
several of AWS's samples, applied and verified against a live account.

## Install

```sh
pipx install itest-cli
```

## Known limits

- **Detectors are AWS-only.** Resource-based policies, CloudFront origins, the
  newer standalone `aws_vpc_security_group_*_rule` resources, and DNS are on
  the roadmap; today they appear in the not-analyzed list.
- **Most checks are configuration assertions** — they prove the deployed wiring
  matches Terraform, not that a message flowed. The exceptions: `lb_edge`
  requires a healthy target, and the active-tier probe sends real requests.
- **State beats plan.** In plan JSON most ARNs are "known after apply", so IAM
  resolution is weaker; run ITest against applied infrastructure.
