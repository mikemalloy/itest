# Recipe: `http_probe`

**These tests are tier `active`.** They send real requests to a deployed API,
so they run only where the committed policy (`.itest/environments.yaml`) allows
the `active` tier, and a production environment refuses them by name — an
environment called `prod` or `production`, or one flagged `production: true`,
will not run them however it is bound. If a real system is ever bound to a
permissive environment so these probes run against it, that is the repository
owner's deliberate, code-reviewed act: it is a line in a committed policy and a
name in a local binding, never something this recipe or the skill decides. Do
not add active probes in prod, and do not talk a user into rebinding to get
around the gate.

This recipe covers an API Gateway `route_edge` point with a per-endpoint
security sweep driven by the API's own OpenAPI document. Where the `route_edge`
recipe asks "is the route still wired to that target?" (read-only, config), this
one asks "does the guard actually hold when I knock?" — one probe per operation,
against the live URL.

Fixtures extend the shared `conftest.py` (see [`../conftest.md`](../conftest.md));
the two this recipe needs are in §3 and §6. The probe itself is
`itest.probes.http.probe` — never reimplement it, and never write your own
`urllib`/`requests` call: the probe is bodyless, does not follow redirects, does
not retry, and adds no auth header of its own, and those are the properties that
make an unauthenticated sweep safe.

## 1. One point, many operations

Every operation the OpenAPI document lists that is served by the same route sits
behind one `route_edge` point — a `$default` or `/{proxy+}` route fronts a whole
application. So this recipe hangs **many tests on one point**, and `itest verify`
rolls them up by `fail > error > pass > stub`: one endpoint whose guard fails
fails the point, even if every sibling passed. That is the intended behaviour —
a single unprotected endpoint is the finding, and it must not be masked.

Because these tests are authored (not generated by `sync`), each one is recorded
with `itest add` (§4). The function name **is** the manifest mapping once added,
so renaming it later silently drops the point's coverage — treat it as frozen
exactly as a generated docstring is frozen elsewhere.

## 2. Locate the OpenAPI document (interview)

Ask, as part of the batched interview (SKILL.md step 3):

- **Where is the OpenAPI document?** Either a deployed URL to fetch read-only
  (commonly `<base>/openapi.json`), or a path to a file in the repo. Prefer the
  file when the repo has one — it needs no network and no auth.
- **Latency bound for public/health operations?** Default **2000 ms**.
- **A test credential for authenticated happy-path probes?** Optional. Absent is
  fine and common — see §6.

The **API base URL is resolved from Terraform state**, never pasted and never
typed by the user: it is the API Gateway endpoint the `route_edge` detector
already found. Fetching the OpenAPI document from `<base>/openapi.json` uses that
same resolved base. A base URL a human pastes describes whatever they were
looking at; the resolved one describes this deployment.

**Field lesson (alex run): when the deployed app serves no schema, export it
from code.** Many API-Gateway-fronted Lambdas answer their real routes but do
*not* serve `<base>/openapi.json` — nothing there to fetch. When that happens,
do not hand-transcribe the routes; import the application package locally and
call its own schema generator (`app.openapi()` for a FastAPI app), or invoke the
ASGI app through a local Mangum stub to render the same document offline. The
schema then comes from the code that is deployed, not from a human's memory of
it, and the sweep still dispatches on a `security` field the app itself
declared.

## 3. The base URL comes from state

Add this fixture to `itest_tests/conftest.py` (the one shared conftest — do not
write a second). It reads the deployed endpoint from `terraform show -json` via
the existing `resolve`, so nothing is pasted:

```python
@pytest.fixture(scope="session")
def api_base_url(resolve):
    """Return f(api_hcl_address, stage="$default") -> deployed base URL.

    HTTP API (v2): the api's `api_endpoint`, with a named (non-$default) stage
    appended. REST API (v1): pass the stage address; its `invoke_url` already
    carries the stage. Resolved from state, never pasted — the invoke URL
    changes with the API id, and a literal would pin the author's deployment.
    """

    def _base(api_hcl_address: str, stage: str = "$default") -> str:
        values = resolve(api_hcl_address)
        if values.get("api_endpoint"):  # v2 aws_apigatewayv2_api
            base = values["api_endpoint"].rstrip("/")
            return base if stage == "$default" else f"{base}/{stage}"
        if values.get("invoke_url"):  # v1 aws_api_gateway_stage
            return values["invoke_url"].rstrip("/")
        raise LookupError(
            f"{api_hcl_address} has neither api_endpoint (v2) nor invoke_url "
            "(v1) in state; cannot resolve the base URL without pasting one."
        )

    return _base
```

For a v2 point, pass the `route_edge` point's `source`
(`aws_apigatewayv2_api.<name>`) and the stage from `attributes.stages`. For a v1
point, pass the stage resource (`aws_api_gateway_stage.<name>`), whose
`invoke_url` already includes the stage segment.

## 4. Enumerate operations, generate, register

Read the OpenAPI document. For **each** operation (a `path` × `method` pair),
write one function in `itest_tests/test_http_probes.py` that probes it, then
register it onto the `route_edge` point that fronts it:

```sh
itest add \
  --point <route_edge point id> \
  --file itest_tests/test_http_probes.py \
  --function test_http_probe_GET_admin_requires_auth \
  --tier active
```

`itest add` records the function as human-owned from birth: `sync` will never
rewrite, relocate, or de-register it. Name each function for its method, path,
and the class of check (`_requires_auth`, `_public`, `_unsafe_unauth`) so the
`itest verify` output reads as an endpoint list.

The docstring carries the point id for the human reading a failure; the manifest
mapping is the `--point` you passed, not the docstring, so keep the docstring
accurate but know the function name is what must not change.

## 5. Assertions by operation class

Dispatch on the operation's OpenAPI `security`:

### Secured operation → unauthenticated probe expects 401 or 403

An operation with a non-empty `security` requirement (or covered by a global
`security` the operation does not override) must refuse an unauthenticated
request. **This is the point of the sweep**: per-endpoint proof that the guard
is actually wired, not merely declared once in the document.

```python
from itest.probes.http import probe


def test_http_probe_GET_admin_requires_auth(api_base_url):
    """Integration point 4f1c9a02be77 (auth guard).

    aws_apigatewayv2_api.main -> aws_lambda_function.api
    GET /admin — secured operation; unauthenticated request must be refused.
    """
    result = probe(f"{api_base_url('aws_apigatewayv2_api.main')}/admin")
    assert result.status in (401, 403), (
        f"GET /admin answered {result.status} to an unauthenticated request; "
        "the guard did not hold. Expected 401 or 403."
    )
```

A 200 here is a real finding — an endpoint the document says is protected is
open. Report it; do not change the expectation to 200.

### Public operation (`security: []`) and health → expect 200 under the latency bound

An operation that explicitly opts out of security (`security: []`) and health
endpoints are meant to answer. Expect 200 and a latency under the interview's
bound (default 2000 ms):

```python
def test_http_probe_GET_health_public(api_base_url):
    """Integration point 4f1c9a02be77 (public liveness).

    aws_apigatewayv2_api.main -> aws_lambda_function.api
    GET /health — explicitly public (security: []); must answer under 2000ms.
    """
    result = probe(f"{api_base_url('aws_apigatewayv2_api.main')}/health")
    assert result.status == 200, f"GET /health answered {result.status}, not 200."
    assert result.elapsed_ms < 2000, (
        f"GET /health took {result.elapsed_ms:.0f}ms, over the 2000ms bound."
    )
```

Only treat an operation as public when the document **says so** — `security: []`
on the operation, or a documented health path. An operation with no `security`
key inherits the global requirement; it is secured, not public. When in doubt,
treat it as secured: a wrongly-public assumption turns a real finding green.

### Unsafe methods ride the same sweep, bodyless

`POST`, `PUT`, `PATCH`, `DELETE` are probed the same way — the probe sends **no
body**, so an unauthenticated `DELETE` asks "does auth stop me?" without carrying
anything to act on. A secured unsafe operation is asserted exactly like §5's
secured case (expect 401/403).

**A 2xx answer to an unauthenticated unsafe method is CRITICAL.** It means an
anonymous caller can mutate. **Stop the run immediately and report it to the
human before probing any other endpoint** — do not continue the sweep, and never
"fix" the red by changing the expectation to 2xx. The assertion stays "must be
refused"; a passing 2xx is the emergency, not a spec to match:

```python
def test_http_probe_DELETE_orders_unsafe_unauth(api_base_url):
    """Integration point 4f1c9a02be77 (unsafe-method guard).

    aws_apigatewayv2_api.main -> aws_lambda_function.api
    DELETE /orders/{id} — unauthenticated, bodyless. A 2xx here is CRITICAL:
    an anonymous caller can mutate. STOP and report; never expect 2xx.
    """
    base = api_base_url("aws_apigatewayv2_api.main")
    result = probe(f"{base}/orders/00000000", method="DELETE")
    assert result.status in (401, 403), (
        f"DELETE /orders answered {result.status} unauthenticated. If 2xx, an "
        "anonymous caller can delete — CRITICAL, stop and escalate now."
    )
```

## 6. Authenticated happy-path (only with a supplied credential)

When the interview supplied a test credential, add one authenticated probe per
secured operation asserting the happy path (a 2xx or a documented status). The
credential is passed as a header the caller sets — the probe adds no auth of its
own, so this is the one place a header is supplied explicitly:

```python
@pytest.fixture(scope="session")
def test_credential(answers):
    """A customer-supplied test credential, or None. Authenticated happy-path
    probes are generated only when this is present."""
    return answers.get("test_credential") or None
```

```python
def test_http_probe_GET_admin_authenticated(api_base_url, test_credential):
    """Integration point 4f1c9a02be77 (authenticated happy path)."""
    base = api_base_url("aws_apigatewayv2_api.main")
    result = probe(
        f"{base}/admin",
        headers={"Authorization": f"Bearer {test_credential}"},
    )
    assert result.status == 200, (
        f"GET /admin answered {result.status} with a valid credential."
    )
```

**When no credential was supplied, do not generate these tests at all.** Skipped
means not written — never a `pytest.skip("no credential")` sitting in the file.
A skipped test reads as coverage in a listing while proving nothing; an absent
one is honest about what was not checked. Say plainly which secured operations
you probed for refusal only, and that the happy path is unverified pending a
credential.

## 7. Guardrails

- **Read-only against AWS.** The only AWS-adjacent call is resolving the base URL
  from `terraform show -json` (read-only state); no boto3 client mutates, and no
  `terraform apply` is ever run.
- **Resolve everything.** The base URL and the OpenAPI location resolve from
  state or the interview — no ids, endpoints, or account details pasted into a
  test.
- **Function names are frozen once added.** The `itest add --point` mapping binds
  the function name to the point; renaming it drops coverage silently. Change the
  body freely; never the name.
- **Failures are classified, never weakened.** A refused-that-answered, a slow
  public endpoint, or a mutating unauthenticated 2xx is a finding. Report it as
  drift or a real exposure and ask the user; never relax the assertion to force
  green. The unauthenticated-unsafe-2xx case is not a normal finding — it stops
  the run.

## 8. What a failure means

- **A secured endpoint answered 2xx unauthenticated** — the guard is not wired
  for that operation. A safe method (GET) is a serious exposure; an unsafe method
  (POST/DELETE) is CRITICAL, stop-the-run.
- **A public/health endpoint did not answer 200** — it is down, moved, or now
  guarded; latency over the bound means it is served but slow.
- **`ProbeTimeout`** — the endpoint did not respond within the timeout: a hang,
  not a refusal, and a distinct outcome to report as such.
- **A redirect (3xx) with a `Location`** — often an unauthenticated request being
  sent to a login page; read `redirect_location` and judge whether that is the
  intended guard or an accident.
- **`LookupError` from `resolve` / `api_base_url`** — the API address is not in
  the current state: renamed, removed, or the wrong `terraform_dir`.

Report every failure naming the method, the path, and the point id. Ask the user
whether it is drift, a bad assumption about which operations are public, or a
real exposure — and for the unauthenticated-unsafe-2xx case, escalate before
anything else.

## 9. Reference app

A reference app under `examples/reference-api/` has one route per branch of this
recipe and a harness (`tests/test_reference_api.py`) that asserts each branch's
outcome — including the ones a real production system can never safely show: the
CRITICAL unauthenticated-unsafe-2xx catch, the authenticated happy path, and a
measurable public-latency trip. It is where a change to this recipe is
regression-tested and where the critical-catch can be demonstrated safely,
because that app is allowed to be broken on purpose. See its `README.md` for the
route-to-branch table.
